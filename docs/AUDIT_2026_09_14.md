An end-to-end audit across six dimensions: data, code, parameters, features,
literature, and staleness. Commissioned because the last two days moved fast
— a 13-table OCR extraction, a 104 → 700 facility expansion, a GBM benchmark,
two leakage tests and a refit — and the concern was "we might have lost
track." That concern is correct, though not mostly in the places one would
guess.

**Method.** Every finding below names the command or the file that
establishes it. Where prose and an artefact disagree, the artefact wins.
Nothing here is inferred from a document's claim about itself. Numbers were
read off disk on 2026-09-14 with `PYTHONPATH=src .venv/bin/python`.

**What is NOT in scope.** A staleness sweep ran in parallel with this audit
and has already corrected roughly 25 documents — `PANEL_EXPANSION.md`,
`MWPVL_OCR_PIPELINE.md`, `NOTES_COVARIATE_LEAKAGE.md` §5,
`docs/data/README.md`, `CLEANING_CHANGELOG.md`, and the "raw covariate beats
the model" claim across `docs/defense/`, `docs/adr/`, `docs/proposal/` and
`docs/review/`. Those are not re-reported. §6 reports only what the sweep
missed.

**Moving targets.** `src/siting_atlas/models/covariate_*.py`,
`panel_*.py`, `docs/research/NOTES_COVARIATE_SEARCH.md` and
`NOTES_PANEL_EXPERIMENTS.md` were being written while this audit ran. They

- **Effort:** 15 minutes to copy the correct PDF into `data/raw/mwpvl/`,

`logs/` contains four OCR logs: `054811` (aborted, `FileNotFoundError:

`data/raw/mwpvl/tsv/SETTINGS.json` has mtime `09-14 06:07` — it was created
*after* the delivery-station strips. The guard had nothing to compare them
against. The defect the guard was written to catch is the defect that
occurred, in the guard's blind spot.

- **Verified by:** `find -newermt` on the TSV tree; `ls -l` on
  `SETTINGS.json`; `ls logs/`; `sed -n 195,220p scripts/grid/grid_ocr.py`.
- **Cost:** The upscale/psm/strip/overlap settings used on the most
  important table are unrecorded. If they differed from the recorded
  `{4, 6, 1400, 400}`, the DS rows and the non-DS rows were read under
  different optics and the row-merge rate measured on one does not apply to
  the other.
- **Effort:** 30 minutes — `rm -rf data/raw/mwpvl/tsv` and re-run the whole
  extraction in one pass with one log, then diff `mwpvl_facilities.csv`
  against the current copy. If it is byte-identical, the worry is closed with
  evidence.

### 1.4 The panel is a cross-section wearing a panel's clothes — HIGH

`data/processed/panel.parquet` is 1,081,312 rows × 50 columns, 33,791 ZCTAs
× 32 quarters. Of the 48 non-key columns, **33 have zero within-ZCTA
variation over time**:

```
$ PYTHONPATH=src .venv/bin/python -c "
import pandas as pd
p=pd.read_parquet('data/processed/panel.parquet')
for c in p.columns:
    nun=p.groupby('zcta',sort=False)[c].nunique(dropna=True)
    print(c, round(100*(nun>1).mean(),2))"
```

Only these vary within a ZCTA across quarters:

| column | % of ZCTAs that vary over time |
|---|---|
| `electricity_cents_kwh`, `diesel_usd_gal` | 99.56 |
| `permit_units_total` | 95.53 |
| `permits_yoy_pct` | 93.17 |
| `home_value` | 77.72 |
| `rent_index` | 18.54 |
| `rent_index_yoy_pct` | 16.35 |
| `rent_observed` | 13.81 |
| `enabled` | 2.70 |

Everything else — all ACS demographics, all CBP counts, all BLS wages, all
five EJScreen indicators, land area, coordinates — is a single vintage
broadcast down 32 quarters. The cause is visible in `data/interim/`:

```
$ ls data/interim/
acs5_zcta_2023.parquet   (33772, 18)   <- ONE vintage
acs1_metro_2023.parquet  (530, 5)      <- ONE vintage
cbp.parquet              (35002, 6)    <- no year column
bls_wages.parquet        (1571, 9)     <- ONE vintage
ejscreen_tract.parquet   (86082, 11)   <- ONE vintage
```

`warehouse/panel.py:11-13` is honest about this — *"Pinned vintages, not a
time series"* — so this is a known design choice, not a surprise. But the
consequence has not been carried through to the modelling docs. The six
columns the parallel sweep flagged (`pm25`, `median_home_value`,
`diesel_pm`, `traffic_proximity`, `low_income_pct`,
`people_of_colour_pct`) are a subset of the 33. All six **do** vary
cross-sectionally (`pm25` has 3,091 distinct values across ZCTAs), which is
why they remain legitimate inputs to a conditional choice model comparing
ZCTAs at one instant. They are fatal only to a design that compares a ZCTA
to itself before and after.

- **Verified by:** the groupby above; `pd.read_parquet` shapes on every
  `data/interim/*.parquet`.
- **Cost:** Any difference-in-differences, event-study, or fixed-effects
  hazard specification on this panel can identify nothing from 33 of its 48
  columns. `docs/MODEL_SPEC.md` still describes a discrete-time hazard with
  time-varying covariates; on this panel that model has four real regressors
  and a fuel price.
- **Effort:** 3-4 hours to pull ACS 5-year 2018–2023 and CBP 2018–2022 (both
  are already-working keyed/keyless extractors — `ingest/census_api.py`,
  `ingest/cbp_detail.py` — run per vintage) and rebuild. That single change
  converts ~20 columns from constants into series.
