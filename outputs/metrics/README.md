# outputs/metrics — every result the project has

30 JSON files. **Each one is written by a stage of the pipeline and each one is
regenerated by exactly one command.** If a number appears in a document, a
figure, the paper or the deck, it came from a file in this directory.

**Everything here is GENERATED.** A hand edit survives until the next run of
the stage that wrote it and is then gone without a warning. Fix the code, not
the file.

---

## Two rules before you read a number

**1. `docs/NUMBERS.md` is the tie-breaker.** The project's standing rule is
*cite the artefact, not the prose*. When two documents disagree,
[`../../docs/NUMBERS.md`](../../docs/NUMBERS.md) is the single source of truth
— it was re-derived from these files directly, and it lists the stale variants
of each figure so you can sweep them out of anything you write.

**2. Do not trust the stamp on its own.** Most files carry `run_id` and
`written_at`, written through `common/log_json.write_json`. That is normally
how you date an artefact. But `covariate_search.json`'s emitter has
historically **reused one `run_id` across several writes and stamped
`written_at` at the first write**, so the stamp can be older than the content.
Check a payload field instead — `facilities: 687` and the `stage_ledger` for
that file. Several other artefacts carry no stamp at all and are datable only
by file mtime, which any copy destroys.

The long-form version of this page, with per-file sizes, stamping status,
known cross-artefact disagreements and the full history, is
[`../../docs/data/ARTEFACTS.md`](../../docs/data/ARTEFACTS.md). Read that when
you need the argument; read this when you need the command.

## The choice model

| artefact | what it measures | regenerate with |
|---|---|---|
| `choice_report.json` | the production conditional logit — 94 decisions, 56 fit / 38 held out | `make model` |
| `refit_expanded.json` | the same code and the same seed on the original panel vs the expanded one | `make refit` |
| `panel_experiments.json` | five panel-composition arms, stratified and directly standardised top-10 lift, 50 re-splits | `python -m siting_atlas.models.panel_experiments` |
| `gbm_benchmark.json` | the atheoretical LightGBM benchmark `MODEL_SPEC.md` §9.4 specified, 50 re-splits | `python -m siting_atlas.models.gbm_benchmark` |

Two cautions carried over from `ARTEFACTS.md`: quote `panel_experiments.json`
by **field path and named arm**
(`arms.<arm>.methods.conditional_logit.standardised.top10.lift`), and in
`gbm_benchmark.json` quote `across_repeats`, never the `headline_split` GBM
rows — the single split moves under perturbations smaller than a float
round-trip, and the artefact says so in its own `caveats`.

`leakage_test.json`'s two arms are fitted on different decision counts (94 and
100). That asymmetry is unresolved; `leakage_decisive.json` is the file that
controls for it by fitting on the intersection.

## The pre-registered metro test

| artefact | what it measures | regenerate with |
|---|---|---|
| `metro_entry.json` | execution of `docs/PREREG_METRO_MODEL.md` — which metro gets the next facility, on seven held-out years | `make metro` |

This one is special. It carries `prereg_md5`, the md5 of the sealed
pre-registration it executed, and **CI fails the build if that hash does not
match `docs/PREREG_METRO_MODEL.md` on disk** (`.github/workflows/ci.yml`, job
`documents`). If they ever disagree, either the pre-registration was edited
after the result or the result came from a different one. Do not edit either
file casually; see [`../../.github/README.md`](../../.github/README.md) and
[`../../reproducibility/seals/README.md`](../../reproducibility/seals/README.md).

## Regenerating

```
make reproduce    cost, model, scope, figures -- offline, no keys, from the
                  two data files that ship with the repository
make all          the whole offline pipeline, L1 through L5
```

Everything else in the tables above is a one-off analysis rather than a
pipeline stage, and has no `make` target on purpose. Run it by module name.

**Not every module takes `--help`.** Several of these emitters have no
argument parser, so invoking them with a flag runs the analysis. Read the
module docstring first if you only wanted the usage.
